# 初回の新フローで見つかった課題

2026-10-24。案件編集とStudio共通改修を区別する。

| 課題 | 対応 | 範囲・証拠 |
| --- | --- | --- |
| 公式引用の許容URLと表示名義がAI製品向けに限られていた | PHP・IPA・JPCERT/CCの限定HTTPSパスを追加。名義をホストに合わせる | 共通Shorts。PythonとTypeScriptで類似ホスト・query・任意ページを拒否するテスト |
| 約50秒の採用案を既存尺のvalidatorが扱えない | 許容尺へ50秒を追加 | 共通Shorts。1200frame、最大8秒カット、原稿一致は維持 |
| 短い引用や人物導入の後に説明が単調になる | 9カットで、人物・役割比較・公式引用・危険・担当者への質問・更新・調査・追加告知・結論に分けた | 案件編集。モバイル幅の描画画像で数字と文字を確認 |
| 新しいComfyUI入力ディレクトリが2段あり、既存生成器の相対パスと不一致 | input直下に案件専用ディレクトリを置き、別ジョブへ修正 | 案件ドライバー。最初のHTTP400は検証拒否で未実行。原記録を保持 |
| 生成器の来歴項目が人物IDではなく参照画像パスを要求 | spec v02で画像パスへ修正し、既存の完了historyから再検証 | 案件ドライバー。生成の再送なし。元のspecも保持 |
| ブラウザー撮影のバイト列がJPEGで、PNG拡張子だけでは検証に通らない | 元の取得バイトを保持し、復号画素一致のPNGを別途作成 | 案件撮影。見かけの画素数増加や高画質化とは扱わない |
| 音声原本をCONTENT配下へ保存したが、編集器の入口manifestはSHORT出力配下が必要 | 音声原本とproofを動かさず、同一内容のmanifestをSHORT出力へ配置 | 案件ドライバー。Aoedeの9件を再生成せず、全proof・PCM一致を確認 |
| レビューHTMLが公式引用まで図解と説明してしまう | 公式引用がある場合は公式画面と自作説明を含む旨に切り替える | 共通レビュー表示。動画内へ制作都合の注釈は入れない |

## 保留・運用上の限界

- ローカルMiniMax H3は時間がかかる。生成前に構成・人物版を確認し、手戻りの多い段階で量産しない。
- 文字量に基づく字幕の細分化は音声認識による単語アラインメントではない。最終試聴でタイミングも確認する。
- AIによる画像確認、ファイルの技術検証、人による試聴を分ける。
- Driveのmetadata確認で、ユーザーのスマホ実機の再生成功まで断定しない。
- PHPの新しい告知が追加された場合は主張・関連場面・説明欄を再確認する。他の案件を一括で作り直さない。
