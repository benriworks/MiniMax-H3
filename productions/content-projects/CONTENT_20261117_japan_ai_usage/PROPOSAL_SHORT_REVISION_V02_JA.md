# ショートv02｜顧客に合わせた提案書を作る

対象は `japan-ai-short v02`、2026年11月17日。題名は「【Claude】日本は利用指数32位。仕事のAI活用、何から始める？」。

> この動画なんだけど、あなたならどの仕事から始めますか？で、会議メモはレベルが低すぎる。
> エージェント機能で、自社の提案書テンプレートから、お客様固有の提案書をまとめ上げる使い方にして欲しい。人が最終的に確認して仕上げた方がいいね、と伝えて。

## 実演で確認した工程

Claude Code 2.1.316とClaude Haiku 5.5を使用。お客様・自社の資料・数値はすべて架空。作業用フォルダーで `Read` を3回、`Write` を1回実行し、初稿のファイルが作成されたことを確認した。

1. [自社の提案書テンプレート](proposal-demo-v02/proposal-template.md) から4つの見出しと順番を取る。
2. [顧客の商談メモ](proposal-demo-v02/discovery-notes.md) と [自社の提案条件](proposal-demo-v02/offer-rules.md) を読み、青葉製作所向けの日報集計の提案を作る。
3. [エージェントへの依頼](proposal-demo-v02/agent-request.txt) を実行して保存された [提案書初稿](proposal-demo-v02/observed-proposal.md) と元の3資料を照合した。3拠点の現状、既存Excelの日報共通化、1拠点での試行と評価項目、見積と納期が「要確認」である点を画面へ反映した。

画面は初稿を縦向けに組版した要約。資料に記載のない「担当者ごとに集計基準が揺れる」といった補足も初稿にあったため、元資料から確認できる情報を抜粋した。週6時間は架空の現状の値。確認したのは1回分の入出力で、全拠点での成果と費用・納期は未検証。

実行は `python -X utf8 proposal-demo-v02/run.py --attempt 3`（案件フォルダーから）。作業先を限定し、3入力の読み取りと1出力の編集を許可した。`Write` はファイル編集用の `Edit(./proposal-draft.md)` 規則で許可する。初回は利用枠、次は編集規則の指定で失敗した記録をローカルに残した。最終入力と出力のレシートは案件出力下の `_private/proposal-agent-v02/attempt-03/`。初稿原本とGitへ収録したファイルのSHA-256は `136d61c1beed04f90ed704dd6bd0d8b7014a39d67fa4071c6611fb38e9533710` で一致。
