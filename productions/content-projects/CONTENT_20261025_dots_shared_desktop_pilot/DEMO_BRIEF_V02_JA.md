# どら焼きと案件入力の実演仕様

この仕様は撮影と検証の準備用。実装・生成・登録の完了記録ではない。

## Blenderの実演

撮影対象はdotsのクラウドPC内のBlender。ローカルPCの別案件のBlenderを、dotsが操作した画面として代用しない。Blender MCPスキルのinspect-before-actを守り、クラウド側で接続が確認できないローカルMCPを代わりに操作しない。

作業を始める前に、対象アプリ、表示中のシーン、ファイル、保存状態を確認する。既存シーンは保持し、今回専用の別名コピーと出力フォルダーを使う。MCPやbpyを用いる場合は対象ホストとシーンを確認してから段階的に操作し、形・寸法・保存先を検証する。

モデルの要素は上下の焼き色のある皮、中央のあんこ、皿。実在ブランドの刻印や包装は入れない。修正はあんこの厚み1点に絞る。初回・修正後を同じカメラ角度で残し、保存した `.blend` の実在・容量・hash、再表示した画面、取得した画像を台帳へ残す。

必要な撮影は、クラウド画面の入口、Blenderの全体、モデリング途中、修正前、修正後、別名保存、再表示、最終の見栄え。動画の縦カットに加え、記事用はアプリ全体と詳細を確保する。生成したイラストをBlenderの実演画面へ置き換えない。

## 疑似の案件管理システム

Excelファイルの3行を、入力欄・内容確認・デモ登録・一覧の4段階へ結ぶ。元データは次の架空データを使う。

| 案件ID | 顧客名 | 案件名 | 納期 | 金額（円） |
| --- | --- | --- | --- | ---: |
| DEMO-001 | デモ顧客A | 架空展示会LP | 2026-11-10 | 120000 |
| DEMO-002 | デモ顧客B | 架空チラシ | 2026-11-12 | 80000 |
| DEMO-003 | デモ顧客C | 架空セミナー申込 | 2026-11-14 | 50000 |

合計250,000円。住所・連絡先・口座・実顧客データは不要。初期のデモシステムには登録行を入れず、入力前の画面も保持する。

| 要素 | 必要な振る舞い・確認 |
| --- | --- |
| 環境の表示 | 画面に「デモ環境」。実サービスの名称・ロゴを使わない |
| 入力 | Excelの列と同名のラベル、日付欄、円の金額欄。実際の画面操作が見える |
| 検証 | 必須項目、妥当な日付、非負整数の金額、案件ID重複を検査する |
| 内容確認 | 登録前に1件分を読める画面で表示。元の行に戻って直せる |
| 保存 | 確認後の明示的なデモ登録で保存し、結果を一覧へ反映する |
| 再表示 | 画面を再表示して登録済みの3件を確認。セッションを越える保存は実際の範囲だけを説明する |
| 照合 | 件数3、案件ID3種、全項目、合計250,000円をExcelと比較。重複登録されていないことを確認する |
| 副作用 | 外部への送信・請求・会計計上・メール通知・実サービス接続なし |

クラウド側から開けるデモのURLと接続経路を確認してから撮影する。到達不能ならその事実と代替案を記録し、ローカルの成功画面だけでクラウド実演済みとしない。デモシステムを実装した際は独立した `ARCHITECTURE.md` と `ARCHITECTURE_DIAGRAM.md` を作成する。
