# dots短編試作の制作構成

この案件は、チャットから共通ContentWorkspaceへ採用構成を記録し、dotsクラウド内で架空実演を行い、実画面をローカルのShorts制作処理へ渡す。クラウド上のアプリ操作の証拠と、編集で作る図解・人物演出を区別する。

`produce.py voice --episode N` は既存のGemini合成処理と共通の排他・送信間隔を再利用する。原稿と読み方を固定し、検証済み音声は再利用する。拒否・結果不明の要求は自動再送しない。出力は案件の `voice/NN/v01/`。モデルの再設定やキーの保存は行わない。

共通Shortsが読むmanifestは `outputs/productions/SHORT_20261025_dots_desktop_NN/voice-source-v01.json` に置く。音声本体と各要求の検証記録は案件の出力フォルダーに保持し、manifest内のhashで参照する。第1回では当初のmanifest配置が検証器の許容範囲外だったため、検証済み6要求を再送せず、許容場所へmanifestだけを保存して再利用した。

`produce.py prepare --episode N` は音声manifestと実演キャプチャのproofを共通Shorts処理で照合し、独立した出力世代を作る。画像がまだなければ準備を拒否する。既存のrender-stateがあれば原本hashを確認し、重複準備を避ける。レンダー・全decode・音量検査・画面レビュー・共有は別段階として記録する。

共通処理の追加は20・25・35秒の許容尺。既存の15・30・45・50・60秒は維持する。音声より短いタイムラインは拒否し、各場面を8秒以内に保つ。検証は `tests.test_shorts_pilot_durations` と既存の `tests.test_shorts_creator`。

`capture_assets.py` は取得済みの実画面から、確認済みの矩形を画素変更なしで切り出す。撮影や架空の画面生成は行わない。原本と派生のhash・矩形・日時・確認根拠を保存し、共通検証器へ渡す。非公開原本を公開用の素材集へコピーしない。

`rendered_visuals.py` はクラウド側Blenderの完成レンダー2枚から、完成形と同視点比較の編集映像を作る。これはGUIの連続録画ではない。GUIのキャプチャとは別の素材種別・検証記録で管理し、動画の完成画像と作業画面を切り替える。

`blog_handoff.py` は草稿v03、実アプリの画像、完成レンダー、公式の一文引用を `blog-handoff/v02/` へまとめ、HTMLレビューとhash付きZIPを作る。原本の実解像度を記録し、拡大だけで記事用の高解像度取得としない。記事の公開やblogへのコピー・マージはしない。

`register_workspace.py` は既存人物の継続範囲、MiniMax素材、実演キャプチャ、実測場面尺、記事の素材割当を共通ContentWorkspaceへ保存する。既存人物の継続指定と、今回の完成クリップの最終採用を区別する。共通チェックの `ready_for_production` は準備状態であり、技術検証や人の試聴の完了を示さない。結果を先に見せる構成では「problem」から始めないため、人物の物語要素に関する共通警告を残して制作記録で確認する。

レビュー画面の共通改善として、実演キャプチャを含む作品に従来の「開発画面は図解」という説明を表示せず、架空素材による実画面と編集を含む旨を表示する。

`article_pdf.py` は草稿と公開候補画像から日本語フォントを埋め込んだPDFを作る。PDFのページ画像化と文字抽出で確認し、途中のレイアウト版と最終レビュー版を保持する。`finalize_review.py` は技術検証済み候補へAI画面確認の記録を添え、共有済みファイルの容量・保存先と原本hashを照合する。既存の納品台帳があれば再検証だけを行い、完成物や確認記録を再書き込みしない。

制作窓口はチャット、レビューはDrive優先。原本・派生・改訂・公開候補をローカルの版付きパスとhashで管理し、Gitにはコード・原稿・出典・設計・検証要約だけを残す。動画・音声・ZIP・非公開撮影原本はGitへ入れない。

v02は `build_revision_v02.py` で旧構成を残したまま改訂する。`produce.py` の `--version v02` は読み方規則を長い一致から適用し、実際に送る読み上げ文が同じ場面だけ旧音声を再利用する。表示文が同じでも読み方変更があれば再合成する。今回の新規要求は10、再利用は10場面。検証は `tests.test_pilot_narration_reuse` を追加した。人物動画やBlender完成物の再生成は行わない。

記事は `blog_handoff.py --version v03` が草稿v04と画像10点をまとめる。`article_pdf.py --article-version 4` は画像とキャプションを同一まとまりにして9ページへ出力する。v02動画・記事PDF・素材ZIPはDrive保存後に名前・容量・MIME・保存先を読み戻し、ローカルの納品台帳 `delivery-v02.json` へ記録した。最新版のブラウザー再生と人の試聴は未確認。

`register_revision_v02.py` は修正依頼の原文と反映方針、変更後の意図、実測場面尺、追加素材、記事v04を共通CLIへ記録する。修正制作の実行指示と完成物の最終採用を分ける。準備チェックが通っても、技術検証・人の試聴・公開フラグを自動的に完了へ変更しない。
