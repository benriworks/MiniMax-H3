# Docsの共同編集を伝える構成への修正

更新：2026-10-23。ユーザーのv01レビューを反映した構成案。動画v02の生成・追加撮影は未実施。

## ユーザーの評価と、今回の問題

- 音声は良いという評価。Aoedeの声、速度、音質の方向を維持する。旧音声の評価を、新しい原稿の試聴済みという意味に広げない。
- v01は「文書が作れる」「数字を照合する」に説明が寄り、Docsの製品価値を説明できていなかった。
- 伝える中心は「様々な資料を踏まえ、人とClaudeが同じ文書を見ながら完成へ近づけること」。予算欄の太字は、その一場面に下げる。

## 主張と画面を対応させる

| 伝える内容 | 次版で見せる画面 | 現在の証拠 |
| --- | --- | --- |
| 同じ文書を育てる作業場所 | チャットとDocs本文の全体。成果物の画面を主役にする | 実演アプリと公式資料。紹介用の広い撮影は追加する |
| 資料や会話を下書きに生かす | 架空の企画メモと打合せメモ、生成文書の対応箇所 | 公式説明あり。2資料を渡す新しい実演は未実施 |
| 人が文書へ直接手を入れる | 本文をクリックし、自分で一語直す前後 | 公式説明あり。直接入力の実演は追加撮影が必要 |
| 箇所を指定してClaudeに相談する | テキスト選択、コメント、応答、文書への反映 | コメント経由の作成と修正の保存記録あり。操作のつながりを追加撮影する |
| 文書向けの編集機能 | 見出し、表、書式の操作と本文を同じ画面で示す | 公式は見出し・表・タブ等を説明。既存画面の一部分だけでは全体が伝わらない |

複数人の同時編集は、AIと人の共同編集とは別の機能説明として扱う。編集権限等の条件がある。今回は別ユーザーとの同時編集を実証済みとしない。

## 従来との差を誇張しない

従来のArtifactsにも文書生成と会話横の表示はあった。「文書を作れる」「プレビューがある」「資料を読める」だけを初めて可能になった機能として紹介しない。今回の解説では、文書の編集・相談・更新を一つの作業の流れとして見せ、その使い勝手を伝える。

## 次版の制作方針

- 見出し案：**【Claude】Docsは「一緒に仕上げる」文書作成。人とAIの共同編集**。
- 尺の構成案：45秒。説明を詰め込むより、文書に人が手を入れ、Claudeが反映する前後を読める時間を確保する。
- 同じ架空店舗と人物を継続。人物は冒頭と締め、編集の中心場面は実際のアプリ画面を大きく使う。
- 読み上げの声・速度・音質の方針は維持し、原稿は中心メッセージに合わせて変更する。
- ブログも共同編集の流れを入口にする。数字の照合は具体例として残し、資料参照や直接編集の未実証部分を公式説明と区別する。
- 出力例の画像だけで操作が伝わったと判断しない。入力資料、同じ文書、人の編集、Claudeへの依頼、更新結果をつなげる。

## 今後の企画で追加する確認

1. 動画を見終えた人に残す一文は何か。
2. その一文は、従来もできた一般的なことだけになっていないか。
3. 製品の機能、説明上の利点、実際の検証結果を分けているか。
4. その価値を証明する画面が台本にあるか。
