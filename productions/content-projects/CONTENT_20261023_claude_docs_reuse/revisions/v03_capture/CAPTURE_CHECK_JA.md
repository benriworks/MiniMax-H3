# Claude Docsの実機キャプチャ確認

確認日：2026-10-23。ユーザーから「解説を作るときには、まず画面キャプチャを取れないか確認してほしい」と指示を受け、実機で確認した。

## 結果

**ユーザーPCのClaude DesktopでDocsを開き、画面を保存できた。** 撮影対象は既存の架空店舗「灯台珈琲」の企画書。アプリのArtifacts切り替えからDocsを選び、見出し、本文、表、編集ツールバー、Commentsペイン、文章選択時の編集メニューを確認した。

| カット | 確認できたこと |
| --- | --- |
| Docsパネル | 実アプリ内に文書を表示できる |
| 展開した編集画面 | 文書の見出し、表、価格、日程、ネイティブの編集ツールバー |
| Commentsペイン | コメント欄の入口と解決済みスレッドの存在。スレッド本文は開かない |
| 文章の選択 | 架空の目的文を選択し、Claude編集とコメントを含むツールバーが表示される |

今回は表示と文章選択だけを行い、本文や数値を変更せず、新しいプロンプトやコメントも送信していない。直接入力による保存、複数資料の参照、新規コメントからの更新を実演済みとはしない。今回の結果は「撮影できる」の確認であり、既存動画の差し替えはまだ行っていない。

## 保存先

`outputs/content-projects/CONTENT_20261023_claude_docs_reuse/captures/20261023-native-v01/`

- `_private/`：JPEG撮影原本と取得条件。
- `public/`：公開候補の切り出しと照合記録。
- `capture-manifest.json`：元画像、座標、hash、画素照合。
- `index.html`：4カットの確認入口。

Computer Useが返した画像はJPEGであり、そのまま原本として保存。公開候補はデコード後の矩形をPNGに保存し、画素一致を確認した。PNGへ変換しても元の解像度・情報が回復したとは扱わない。文章選択の最初の切り出しは見出しの一部が切れたため、文脈を含む候補を別ファイルとして保存した。

## 今後の制作ルール

台本や代替画像を固める前に、対象機能をユーザーPCで開き、表示、保存、文字の読みやすさ、必要な操作の撮影可否を確認する。取得できない場合は、試した経路と観測した理由を残す。既存画像や公式説明だけで構成を確定する前に、この確認を行う。
