# Codex 15秒ショート: カット計画

制作ID: `SHORT_20260905_codex_15s`

象牙色・墨色・ミント色を使ったエディトリアル調の縦動画です。実画面を撮影した映像ではなく、Codexへ依頼して実装・確認へ進む流れを示すオリジナルのモーショングラフィックスです。公式ロゴは使わず、製品名を文字として表示します。

| カット | 素材尺 | 主な画面 | 読み上げ |
| --- | --- | --- | --- |
| 1 | 126 frame / 5.25秒 | 「作りたい。を、言葉に。」から、プロンプトの入力とタスクカードの出現へ | 作りたいものを、言葉で伝える。 |
| 2 | 126 frame / 5.25秒 | 「実装から、テストまで。」、コードの変更案、確認項目を順に表示 | Codexが、実装やテストを手伝う。 |
| 3 | 120 frame / 5.00秒 | 「確かめて、次の一歩へ。」、Codex、依頼→実装→確認。「まずは、小さな改善から。」で結ぶ | 成果を確かめて、次の一歩へ。 |

合計15.5秒の素材から2箇所の250msフェード分を引き、完成15秒にします。全素材は1080×1920・24fps・H.264の無音MP4です。音声と読み上げ字幕は、既存のSAPI・Remotion・assembly・QCの処理関数を使った制作専用の実行スクリプトで後付けします。通常のQuickCreate画面から実行した制作ではありません。ソース内に大見出しがあるので、後工程の各clipは `overlay: null` とします。

カット1・2のコードやUIは説明用の図案であり、実際の操作キャプチャ、完了したテスト、性能を示しません。「ワークフローのイメージ」を明記します。タイプ表示、時間差で現れるカード、描かれるチェックマークと約1.2%の緩い全体移動を使い、後半も動きが続く構成です。

重要な文字と図はおおむねx=96〜896、y=297〜1405に収めます。y=1510〜1740は後工程の大きな読み上げ字幕のために空け、右側160pxは重要情報を置かない構成です。フォントはWindowsにあるYu Gothic系・Consolasを使い、外部フォントやネットワーク画像は読み込みません。

## 再現

リポジトリルートで、まず代表静止画を作成します。

```powershell
node productions/SHORT_20260905_codex_15s/render.mjs --stills
```

文字の切れと字幕の余白を確認したら、3本の動画素材を作成します。

```powershell
node productions/SHORT_20260905_codex_15s/render.mjs --videos
```

出力先は `outputs/productions/SHORT_20260905_codex_15s/sources/` です。各MP4、代表PNG、処理時間・SHA-256を含むレポートを保存します。依存ライブラリは既存の `studio/node_modules`、ブラウザーは同じPlaywrightが指すインストール済みChromiumを使用します。

## 素材生成結果

3カットの代表静止画を実画像で確認し、主文字の切れや字幕領域への侵入がないことを確認してから、全素材をレンダーしました。

| 素材 | フレーム数・長さ | サイズ | レンダー時間 |
| --- | --- | --- | --- |
| `cut_01_prompt.mp4` | 126 frame・5.25秒 | 401,419 bytes | 29.273秒 |
| `cut_02_build.mp4` | 126 frame・5.25秒 | 426,102 bytes | 28.945秒 |
| `cut_03_review.mp4` | 120 frame・5.00秒 | 390,620 bytes | 28.604秒 |

全3本を独立したffprobeで1080×1920・24fps・H.264・音声streamなしと確認し、FFmpegの全フレームdecodeも成功しました。元の大見出しは素材内に含まれています。代表静止画は最終レイアウトを示し、動画では「ワークフローのイメージ」を冒頭から表示するタイミングへ調整しています。各ファイルのSHA-256は同じ出力先の `sources-report.json` に記録しています。
