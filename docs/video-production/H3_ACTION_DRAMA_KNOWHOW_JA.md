# 静止画から作る短編アクションドラマ（MiniMax H3）のノウハウ

2026-11-15作成。「灰の街」3分版（36カット×5秒、縦1080×1920）の制作で分かったことをまとめる。案件の経緯と数値は [案件の再開記録](../../productions/content-projects/CONTENT_20261112_hooded_rooftop_landing/RESUME_AND_KNOWHOW_JA.md) と、同じフォルダーの `RESUME_JA.md`（制作PC上の時系列ログ）にある。

## 全体の流れ

1. **監督プラン**: シーンごとに5秒カットの表を作る（画・動きと音）。足した設定は「説明なしで筋が通るか」で選び、ユーザーの確認を取る。
2. **設定画**: シーンで新しく出る人物・場所・小道具ごとに1枚（三面図＋顔、場所は無人の全景）。以後のカットはこれを参照画像にする。
3. **絵コンテ**: 各カットの始端（必要なら終端）の静止画をGemini画像（`gemini-3-pro-image`、9:16）で作る。一覧画像を作って自分で見て、直してから次へ進む。
4. **ローカル試作**: ComfyUI（Q3 GGUF＋Turbo LoRA、480×864、8ステップ）で全カットを1本ずつ。RTX 3070 Ti 8GBで1本約5分。
5. **API仕上げ**: MiniMax H3（768P、5秒、`ratio=adaptive`）。並行に投げてよく、1本2〜3分。1秒あたり約0.08米ドル（記憶による概算）。
6. **連結と後処理**: カット一覧のIDで連結し、字幕・声・画面の文字・時間のテロップを後から重ねる。生成した動画に文字を描かせない。

## スクリプト

すべて `productions/content-projects/CONTENT_20261112_hooded_rooftop_landing/` にある。メディアは `outputs/`（Git管理外）。

| スクリプト | 役割 |
| --- | --- |
| `layout_guide.py` | 寸法どおりの下絵（2つの屋上、隙間2m、段差1m、身長1.65mの目印、階段室）をz-bufferで描く。カメラ位置・注視点・縦画角を引数に取る |
| `gen_plate.py` | Gemini画像。プロンプトのファイルと参照画像（`--ref` 複数）。既存ファイルは上書きしない |
| `comfy_shot.py` | ローカルComfyUIで1カット。`--last-image` で両端参照 |
| `generate_h3_shot.py` | H3 APIで1カット。`--confirm-billable` 必須。`generation.json` にタスクIDを残し、途中で止まっても再投入せずに再開できる |
| `cuts_catalog.py` | 全カット（不採用・試作も）の一覧。ディスクにあって一覧にないカットがあるとエラーで止まる |
| `assemble_sequence.py` | 一覧のIDを並べて連結（各5秒、24fps、−14 LUFS） |
| `gen_tts.py` | Gemini TTS（`gemini-2.5-flash-preview-tts`）で1行をWAVに |
| `add_news.py` | ニュースの字幕帯と声を重ね、その区間の元の音を0.3倍に下げる |
| `add_screen_text.py` | 通信機の受信画面（緑の文字が一文字ずつ出る）を重ねる |
| `add_titles.py` | 「3日前」「現在」のような時間のテロップ（明朝、左下、フェード） |

プロンプトは `prompts/<シーン>/make_prompts.py` が書き出す形にした。共通の言い回し（色調、人物の説明、文字を出さない指示）を変数にまとめると、12枚を一度に直せる。

## 静止画（絵コンテ）の学び

- **高さ関係は文章では通らない。** 「1m高い」と書いても見下ろしや数階分の差になる。効いた順に、(1) 既存の採用画を土台に人物を足す・消す編集、(2) 寸法どおりの下絵＋素材の参照だけで「形を変えず写真に」、(3) 文章のみ。下絵に人物の参照まで足すと、参照の構図に引っぱられて下絵が無視された。
- **参照画像は少ないほど指示が通る。** 空撮の参照を入れると、どんな指示でもその構図に戻った。人物の参照（顔＋衣装）と場所の参照は、カットに必要な分だけ渡す。
- **細部の修正は「この画を編集。〜以外はすべてそのまま」。** フードを下ろす、ガスを消す、などは1回で通った。
- **厚みや材質は否定と比喩で書く。** パラシュートは「帆のように薄い翼形。クッションや布団ではない」で直った。
- **向き**: 1枚が横倒しで出た。縦9:16で人物が立っていると明記して作り直した。
- **ニュース映像**: 「TVニュースの画」と書くと、横長の画を縦の中央に置き上下をぼかした形で出た。縦型ショートでよく見る形なので採用し、字幕は下のぼかし部分に置いた。
- **左右の取り違え**: 正面を向いた人物の「左頬」は画面の右。設定画と照らして確認する。

## 動画（H3）の学び

- **始端のみ参照で十分なカットが多い。** 両端参照は、終わりの姿勢を決めたいとき（パラシュートが開いた画など）に使う。
- **「どこで終わるか」を書く。** 助走のカットでは、カメラが追う構図だと縁を越えて空中を走った。引きの固定カメラにして「最後に縁の上に足をかけて終わる。屋上から出ない」と書くと直った。
- **速さは明示する。** 「in slow motion」と書いたらその通りになり、ユーザーから「スピード感を」と指摘された。「real-time, NOT slow motion」「カメラが振り向いて追う」「最後まで止まらない」で直った。落下中も人物を画面中央に残すよう書かないと、途中で消えて別の街に変わることがある（ローカル試作で発生）。
- **出力審査**: 隊員が銃を持って橋をふさぐカットが `new_sensitive` で止められた。「秩序だった道路封鎖」「何も劇的なことは起きない」と書き直すと通った。発砲は「銃口の光が顔を照らす。撃たれる側は映さない」、倒れる人は「血も傷も映さない」で通った。
- **ローカル試作の価値**: 動きの方向や構図の破綻は480×864でも分かる。ただしローカルで起きた問題（人物が消える、別人が出る）がAPIでは起きないこともあり、その逆もある。最終判断はAPI版のコマ送りで行う。
- **ローカルのメモリ不足**: 8GB GPUで1回OOMになった。モデルを解放した後の再実行で通った。出力フォルダーは再利用されないので `-t2` で作り直す。

## 確認の仕方

- 生成のたびに、1秒ごと5コマを横に並べた一覧画像（`ffmpeg -vf fps=1,scale=120:-1,tile=5x1`）を作って見る。問題のカットは0.25秒刻みで詳しく見る。
- 通しは尺（フレーム数）と、声を入れた区間の音量を `volumedetect` で確かめる。
- 共有フォルダーは20MBまでなので、確認用に720p（CRF 26〜29）を別に作る。3分で約16MB。

## 進め方の学び

- ユーザーの指摘は「何秒目のどこが、どう見えるか」で来る。その秒数からカットを特定し、縮めるか作り直すかは仕上がりで判断した（今回は2回とも作り直し）。
- 次のシーンの静止画は、前のシーンの直しと並行して進められる（ユーザーの指示）。GPUを使うローカル試作だけは同時に1本。
- 費用は毎回、本数×秒数で見積もって報告する。3分版の累計は約20米ドル（H3約14米ドル、画像約6米ドル）。
