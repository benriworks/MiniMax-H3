02 / Official vs Studio

公式H3と、この個人フォークの違い

競合する2つの生成モデルではありません。公式H3が「撮影・生成エンジン」、Studioが「制作管制室＋編集室」です。

Generation engine

公式 MiniMax H3

テキスト・画像・動画・音声参照から、高品質な映像とnative audioを生成するモデル／サービス。

＋
Production control room

個人フォークの Studio

企画、複数素材、音声、編集、QC、修正履歴、納品、公開ゲートを1つの台帳で扱う制作システム。

03 / Production workflow

15秒コンテンツの制作ワークフロー

チャットからの依頼を、再開可能なJobと中間成果物へ分解します。外部通信や課金がある工程だけを破線で区別します。

  1. 依頼・企画チャットでテーマ、人物、文言、尺、参考画像を決める。
  2. 素材を作る／取り込む既存動画、local T2VA、API I2VA、Web／Windows収録から選ぶ。
  3. 台帳へ固定Production、revision、Run、Job、artifact hashを記録する。
  4. 3場面に編集HOOK、MESSAGE、CTAへ配置し、trim、fade、補正を行う。
  5. 音声・字幕を合成SAPIまたは承認済み音声を使い、clean／captioned版を作る。
  6. QCと人間判断技術検査の後、内容、権利、公開可否を人が判断する。
  7. 納品／限定公開13-entry ZIPを納品。YouTubeはprivate／unlistedのみの別承認。

Technical QCと人間承認の違い
Technical QCは、decode可能性、codec、尺、音量、true peak、黒画面、静止区間、hashなどの機械検査です。内容の良さ、肖像・音源・素材の権利、公開してよいかという判断は、creative、rights、public_releaseの人間レビューで別に扱います。QC passだけで公開可能とは判定しません。
Windows収録acceptanceがfail-closedである理由
現状の成果物には、映像と音の共通機械可読marker、device-switch試験、親process強制終了試験などの登録証拠が不足しています。requestの自己申告だけでは独立証拠にならないため、校正Jobと証拠artifactを実装して実機で合格するまで、content_sync_verified=false、public_release_ready=falseを維持します。

07 / Delivery principles

実用化まで守る線引き

「速く機能を増やす」ことと「確認していないことを成功扱いしない」ことを両立させます。

実装 ≠ 実受入

backend契約やmock testが成功しても、実機、実課金、実provider read-backが終わるまで受入済みにしません。

QC ≠ 公開承認

機械検査と、創作内容・権利・公開判断は独立したgateとして記録します。

外部副作用は明示確認

API keyをchatやrepositoryに残さず、課金、upload、公開範囲を操作直前に再確認します。
